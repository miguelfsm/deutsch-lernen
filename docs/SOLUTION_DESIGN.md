## 1. Architecture Overview

A single-page React application, built by Vite into static assets, deployed to a
free static host and served over a CDN. Each of the existing JSX tools becomes a
routed page inside a shared navigation shell. The app is made installable as a
PWA so it runs full-screen on iPhone/iPad.

```
┌─────────────────────────────────────────────────────────┐
│  Browser / Home-screen PWA (desktop, iPhone, iPad)        │
│                                                           │
│  ┌─────────────┐   App shell (nav + layout)               │
│  │  Nav shell  │──────────────┬───────────────┐           │
│  │ (sidebar /  │   /tool-a     /tool-b   /tool-c ...       │
│  │  tabs)      │   ┌────────┐ ┌────────┐ ┌────────┐        │
│  └─────────────┘   │ Tool A │ │ Tool B │ │ Tool C │  ...   │
│                    └────────┘ └────────┘ └────────┘        │
│         (each tool = a route, full viewport)              │
└─────────────────────────────────────────────────────────┘
                          ▲  static assets (HTML/JS/CSS)
                          │
                  ┌───────┴────────┐
                  │  Static host /  │  ← GitHub Pages (confirmed)
                  │      CDN        │     Cloudflare/Vercel/Azure SWA (alt)
                  └───────┬────────┘
                          │ build on push
                  ┌───────┴────────┐
                  │  GitHub repo    │  ← CI (GitHub Actions) builds & deploys
                  └────────────────┘
```

## 2. Technology Stack & Rationale

| Concern | Choice | Why |
| ------- | ------ | --- |
| Build tool | **Vite** | Fast dev server + simple static build; first-class React support. |
| UI library | **React** | The 4 artifacts are already React/JSX — direct reuse. |
| Language | **JSX/JavaScript** (TypeScript optional later) | Lowest-friction port of existing artifacts; can adopt TS incrementally. |
| Styling | **Tailwind CSS** | Claude artifacts typically assume Tailwind utility classes. |
| Icons | **lucide-react** | Common default in Claude-generated components. |
| Routing | **react-router** | Maps each tool to a URL; enables the nav shell. |
| PWA | **vite-plugin-pwa** (Workbox) | Manifest + service worker with minimal config. |
| Hosting | **GitHub Pages** (confirmed) | Free, simplest, tied to the repo; build runs entirely on GitHub — no Azure needed. |
| CI/CD | **GitHub Actions** | Build on push, deploy to Pages; no extra accounts. |

> Exact dependency set (e.g. shadcn/ui, Radix, framer-motion) will be confirmed
> against the actual JSX files when collected.

## 4. Navigation & Page Model

- `App.jsx` renders a **persistent shell**: a sidebar (desktop/tablet) that
  collapses to a hamburger/tab bar (phone), plus an outlet for the active tool.
- Each tool is a **self-contained module** under `src/tools/<tool>/` exporting a
  single page component, mounted at its own route (e.g. `/vocab`).
- A **home route** (`/`) lists the tools as cards/links.
- Adding a tool = add a folder + one route entry. No changes to other tools
  (satisfies PRD FR6).

## 5. Porting the Existing Artifacts

Each Claude artifact is currently a single self-contained component assuming an
ambient environment (Tailwind, icon library, sometimes inlined UI primitives).
Porting steps per artifact:

1. Drop the component into `src/tools/<tool>/`.
2. Resolve implicit imports into real dependencies (icons, UI kit).
3. Replace any hard-coded full-screen assumptions with the shared layout.
4. Move large static data (word lists, exercises) into co-located data files.
5. Verify it builds and renders in the dev server.

## 6. Build & Deployment

**Confirmed host: GitHub Pages** (decision 2026-06-21)
- The entire build + deploy runs on GitHub's infrastructure — **no Azure is
  involved in hosting**.
- A GitHub Actions workflow (`.github/workflows/deploy.yml`) runs on push to the
  default branch: `npm ci` → `npm run build` → deploy `dist/` to Pages.
- Vite `base` is set to the repo path for project Pages (or `/` for a custom
  domain / user Pages).

**Alternatives (no code change, swap the deploy step):**
- **Cloudflare Pages** — unlimited bandwidth, connect repo, build `dist/`.
- **Vercel / Netlify** — auto-detect Vite, per-branch preview URLs.
- **Azure Static Web Apps** — free tier; integrates with the Azure setup in this
  repo and can add managed Functions later. (Requires an active Azure
  subscription; see §8.)

Portability is preserved because all hosts serve the same static `dist/` output.

## 7. PWA / Installable App Design

- `vite-plugin-pwa` generates the web app manifest and a Workbox service worker.
- Manifest: name, theme/background colors, `display: standalone`, and icons
  (192px, 512px, plus a maskable icon).
- On iPhone/iPad: Safari → Share → **Add to Home Screen** → launches full-screen
  with its own icon (satisfies PRD G6/FR5).
- Caching strategy: precache the app shell; optionally cache tool assets for
  offline use (PRD FR7, "Should").

### Future native path (Capacitor)
If a true native app is later desired, **Capacitor** wraps the same `dist/`
output into an iOS project openable in Xcode, producing an installable `.ipa`
and an App Store path. Reuses essentially all code; requires Xcode and (for
device/App Store) an Apple Developer account. **React Native is intentionally
avoided** because it would require rewriting the UI.

## 8. Cloud-Session & Azure Integration

> **Status: DEFERRED / OPTIONAL (decided 2026-06-21).** Hosting on GitHub Pages
> needs **no Azure** — build and deploy run entirely on GitHub. The Azure
> integration below is unrelated to hosting; it exists only to let Claude Code
> manage **Azure resources** from cloud sessions, and is relevant only if we
> later adopt **Azure Static Web Apps** or other Azure services. The `AZURE_*`
> secrets and subscription reactivation are **not required** for the current
> plan; the SessionStart hook stays in the repo as a harmless no-op until then.

This repo also contains infrastructure to let Claude Code operate from ephemeral
cloud-container sessions (Claude Code on the web, including iPad/iPhone):

- **`.claude/hooks/session-start.sh`** — a SessionStart hook that authenticates
  the Azure CLI as a **least-privilege service principal** (scoped to a single
  resource group, `Contributor`), but **only** in remote sessions
  (`CLAUDE_CODE_REMOTE=true`). It skips on local sessions and when the `AZURE_*`
  secrets are absent, installs `az` if missing, and never echoes secrets.
- Required environment secrets (set in Claude Code's config, never in the repo):
  `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`, `AZURE_TENANT_ID`,
  `AZURE_SUBSCRIPTION_ID`.

This Azure plumbing is **independent of hosting**. The app can deploy to GitHub
Pages with no Azure dependency; the service principal is for letting Claude Code
manage Azure resources (e.g. if Azure Static Web Apps is later chosen as host).

> **Note:** As of 2026-06-21 the only Azure subscription (`Pay-As-You-Go`) is
> `Disabled` while the MCA billing account is Active; reactivation is pending
> before the service principal can be created/used.

## 9. Development Workflow with Claude Code

- Work happens in this git repo; changes are ordinary commits with history.
- Local sessions use the developer's persisted `az login`; remote sessions use
  the service-principal hook.
- Canonical product/design intent lives in `docs/PRD.md` and this file; Claude
  Code should consult them before structural changes.
